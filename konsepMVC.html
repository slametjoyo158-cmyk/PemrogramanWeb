BAB 1 — ARSITEKTUR PERANGKAT LUNAK

Memahami Konsep Model-View-Controller (MVC) di Laravel

Sebelum mengenal kerangka kerja modern, aplikasi dibuat secara monolithic unstructured (*spaghetti code*). Pelajari bagaimana pola arsitektur MVC memisahkan tanggung jawab program untuk menghasilkan aplikasi yang rapi, aman, dan mudah dirawat.

Mengapa Harus MVC? Memahami "Spaghetti Code"

Pada pemrograman PHP tradisional tanpa framework, pemrogram sering mencampur kode HTML (tampilan), query SQL (database), dan logika pemrosesan dalam satu file tunggal. Hal ini dinamakan Spaghetti Code.

Sulit Dirawat

Perubahan kecil pada desain HTML dapat merusak query database.

Kolaborasi Buruk

Developer Frontend dan Backend berebut mengedit file yang sama (*merge conflict*).

Tidak Reusable

Logika query SQL ditulis berulang kali di setiap file halaman baru.

Solusi: Separation of Concerns (SoC)

Solusi terbaik adalah menerapkan prinsip SoC, yaitu memisahkan program menjadi modul-modul independen sesuai dengan fungsi dasarnya: Data, Logika, dan Tampilan.

Anatomi Komponen Utama MVC Laravel

1. Model (M)

Data & Logika Bisnis

Bertanggung jawab mengelola data, aturan bisnis (*business logic*), dan interaksi langsung dengan database melalui Eloquent ORM atau Query Builder.

📁 Lokasi: app/Models/Pengaduan.php
💡 Aturan: Dilarang menghasilkan output HTML atau menerima HTTP request langsung.

2. View (V)

User Interface

Bertanggung jawab menyajikan tampilan akhir kepada pengguna. Di Laravel, View ditulis menggunakan Blade Template Engine (`.blade.php`).

📁 Lokasi: resources/views/pengaduan/index.blade.php
💡 Aturan: Tidak boleh melakukan query database langsung atau logika bisnis rumit.

3. Controller (C)

Lalu Lintas & Pemrosesan

Otak pengendali yang menerima input dari pengguna (via Route), meminta data ke Model, lalu menentukan View mana yang ditampilkan sebagai balasan.

📁 Lokasi: app/Http/Controllers/PengaduanController.php
💡 Aturan: Harus "Skinny" (ramping), menyerahkan tugas query mendalam pada Model.

Pintu Gerbang: Router

Pemeta URL

Memetakan URL yang diakses browser (GET, POST, PUT, DELETE) ke metode Controller yang tepat.

📁 Lokasi: routes/web.php

Manfaat Utama MVC

  • Pengembangan Paralel: Frontend & Backend dev bekerja serentak tanpa saling bentrok.
  • Kemudahan Maintenance: Bug pada database langsung ditangani di Model, bug tampilan di View.
  • Kode Reusable: Satu Model dapat melayani banyak Controller & View berbeda.
  • Struktur Rapi: Ribuan berkas tetap terorganisir sesuai kategorinya.

Tabel Pemetaan Komponen MVC vs Restoran

Komponen MVC Elemen Restoran Peran & Tanggung Jawab dalam Sistem
User / Browser Pelanggan Restoran Datang ke restoran, memilih menu, dan memesan makanan (*HTTP Request*).
Router (`routes/web.php`) Buku Menu / Resepsionis Mengarahkan alamat pesanan pelanggan sesuai ke pelayan/controller yang tepat.
Controller Pelayan / Waiter Menerima pesanan, menyerahkan kebutuhan ke dapur/koki, mengambil masakan, lalu menyajikan.
Model Koki / Dapur & Gudang Data Mengambil bahan mentah (database), mengolah sesuai resep (logika), dan memastikan kualitas.
View (`.blade.php`) Piring Penyajian / Hiasan Mengemas hasil masakan agar tampil cantik, menarik, dan mudah disantap pelanggan.
